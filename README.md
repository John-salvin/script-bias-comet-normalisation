# Making COMET Comparable Across Scripts
### Diagnosis and Correction of Tokeniser-Induced Script Bias in Indic MT Evaluation

> **Status:** Under review

---

## What this repository does

COMET is the default quality signal for non-English machine translation, and it
carries an unstated assumption: that a translation's adequacy is reflected in its
score regardless of which script encodes it. This repository tests that
assumption by treating romanisation as a controlled intervention on 7,000
MQM-annotated English→Indic segments — rewriting the target into Latin script
preserves the linguistic content and isolates orthographic form — and then
measures what COMET does. Romanisation removes 93.3% of the between-script
variance in COMET, collapses COMET–human rank correlation by 29–62%, and inflates
inference cost by up to 5.57×, traceable to an inversion in which tokenisation
overhead rises while information density per token falls. The code derives three
inference-time diagnostics (**SBI**, **IPI**, and a **Computational Tax**
decomposition), shows that no per-language post-hoc corrector can repair the
damage — every monotone correction leaves within-language ranking exactly where
it found it — and evaluates **COMET-QN**, a quantile renormalisation onto a common
reference that restores cross-language comparability without touching
within-language ranking.

## Quickstart

Every command below was run end-to-end in a clean virtual environment while
preparing this repository.

```bash
# 1. Environment (Python 3.10-3.12)
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 2. Confirm the committed workbooks are intact
python3 scripts/check_data.py --strict

# 3. Run the pipeline, notebooks 01 -> 12 in order
make notebooks

# 4. Check every reported number against the registry
python3 scripts/verify_paper_numbers.py

# 5. Test suite
python3 -m pytest -v
```

`make all` runs steps 2–4 in sequence. To work through the analysis
interactively instead, `jupyter lab` and open `notebooks/01_load_and_sample_sizes.ipynb`.

No GPU is required and no model is downloaded. COMET, BLEURT, BERTScore, TP and
IP were computed upstream and are committed as columns; this repository
re-derives every reported statistic from those columns.

## The three sample-size bases

Three different denominators appear in the results, and conflating them is the
easiest way to misquote a number. Notebook 01 establishes all three and
`paper_numbers.yaml` records them under `meta.bases`.

| Base | N | Definition | Used for |
|---|---|---|---|
| **Full** | 7,000 | 5 languages × 1,400 MQM-annotated segments | Mean COMET / TP / IP, the ANOVA, Welch's *t* |
| **Working** | 6,995 | Segments carrying a *numeric* human score | Every correlation against the human score |
| **MAR severity** | 1,258 | Marathi segments with a non-`Default` severity label | The severity-inversion analysis |

The five-segment difference between the first two is itemised in notebook 01:
four segments have a blank human score, and one Malayalam segment holds the
string `` `19 `` rather than a number. **None of them is missing a COMET value.**
That is why the ANOVA is reported on the full 7,000 base: it uses metric-side
quantities only, so dropping segments for a missing *human* score would be
arbitrary. Notebook 02 reports the ANOVA on both bases for transparency.

## Environment, seeds and runtime

| | |
|---|---|
| **Python** | 3.10–3.12 (developed and verified on 3.12) |
| **Pinned dependencies** | `requirements.txt` |
| **Split seed** | 42 — 50/50 within-language split via `numpy.RandomState(42).choice`, consumed one language at a time in alphabetical order (notebook 05). The draw depends on both the generator and the iteration order, so both are fixed. |
| **GBM seed** | 0 — `GradientBoostingRegressor(n_estimators=300, max_depth=3, learning_rate=0.05)` (notebook 07) |
| **Permutation seed** | 0 — 5,000-round paired sign-flip test (notebook 02) |
| **Language display order** | GUJ, TAM, MAL, MAR, HIN, everywhere without exception |

Measured runtime on an 8-core CPU, no GPU:

| Step | Time |
|---|---|
| `make notebooks` (all twelve, end to end) | ≈ 6 min |
| `scripts/verify_paper_numbers.py` | ≈ 1 min 20 s |
| `pytest` | ≈ 1 min 30 s |
| `make all` (data check + notebooks + verify) | ≈ 6 min 20 s |

The two slowest steps are the 25,000 rank correlations of the permutation test
(notebook 02) and the ten gradient-boosted fits of the LOLO loop (notebook 07).

## Datasets

### Primary — IndicMT Eval

MQM-annotated English→Indic evaluation data for Gujarati, Hindi, Malayalam,
Marathi and Tamil, created by [AI4Bharat](https://github.com/AI4Bharat):
1,400 annotated segments per language across 7 MT systems and 11 MQM error
types. See [`data/indic/README.md`](data/indic/README.md) for attribution,
citation and how to obtain the raw annotations.

### Controls — WMT24 ENG-DEU / ENG-SPA

Latin-script reference points from the WMT24 General MT shared task, accessed via
[mt-metrics-eval](https://github.com/google-research/mt-metrics-eval).
ENG-SPA anchors the Parity zone (IPI = 0.009); ENG-DEU lands in the Burden zone
(IPI = 0.465) despite using the Latin alphabet, which is what shows that
fragmentation is driven by encoder vocabulary allocation rather than by script
surface. See [`data/latin/README.md`](data/latin/README.md).
